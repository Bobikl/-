漏洞关卡详解
1.覆盖注册漏洞
示例场景：注册接口写入用户记录时使用upsert/merge，或者按主键更新导致“注册即覆盖”。
漏洞成因：唯一标识（邮箱/手机号/用户ID）校验不足，注册流程存在“更新逻辑”。
练习目标：通过注册接口覆盖全部账号（重置密码或更改关键字段）。
步骤攻击建议：
抓取注册接口请求，尝试携带已有用户的主键或唯一标识；
观察响应与数据库变更（如邮箱被替换、密码被重置）。
自检标准：可稳定复现覆盖而占用拥有原账号。
修复建议：严格区分“注册（创建）”与“修改（更新）”；对唯一键做强校验与权力等控制；关键字段允许在受控流程中更改。
2. 发送验证码时邮箱可修改
示例场景：验证码发送接口的收件邮箱来自前端可控参数，输入未验证与账号绑定关系。
漏洞成因：身份验证与绑定校验解除。
练习目标：将验证码发送到攻击者控制的邮箱，然后接管目标账号的验证码流程。
步骤攻击建议：
对发送验证码接口（/send-code 或 /captcha/mail）尝试替换邮箱参数；
使用受邮箱控接收验证码、走后续重置流程。
修复建议：验证码发送目标必须从服务端侧的绑定关系获取；对每次发送做限速与风控。
3.验证码多发
示例场景：同一账户或同一设备短时间内可多次请求验证码，且新旧码并存或覆盖逻辑不合理。
漏洞成因：缺少频率限制、方差控制与状态一致性设计。
练习目标：利用多发逻辑造成验证码预测或干扰真实用户（DoS/社工）。
修复建议：限速、队列、单通道有效码、设备指纹与风险校验；验证码生命周期合理设计（单次有效，使用后失效）。
4.万能密码
示例场景：登录逻辑存在缺陷（如只校验密码非空、错误地比较哈希、误用测试后门密码）。
漏洞成因：鉴权逻辑实现不严谨或传承后门。
练习目标：在未知密码情况下通过特定输入（空字符串、固定值、特殊格式）登录成功。
修复速度：建议完善鉴权逻辑与单元测试；删除任何后门；对登录失败原因与次数做审计与限额。
5. 预设密码
示例场景：创建用户特定或角色默认分配弱密码（如123456）。
漏洞成因：安全初始化不足、口令策略故障。
练习目标：通过默认密码登录目标账号。
修复建议：强制首次登录改密、口令复杂度与历史策略、取消已知弱默认密码。
6.更新关联邮箱越权
示例场景：修改个人信息允许接口更新邮箱，但未验证“原邮箱+验证码”。
漏洞修改成因：关键绑定属性缺少二次确认与强鉴权。
练习目标：替换目标账号绑定邮箱为攻击者邮箱。
修改建议：修改绑定邮箱必须走“原邮箱验证 + 新邮箱确认”身份证流程，并验证会话归属。
7. SQL注入改密码
示例修改场景：重置或数据接口存在 SQL 注入，可直接更新用户设置密码=...。
漏洞成因：未使用参数化查询，输入未充分校验。
修改练习目标：通过注入语句任意用户密码。
修复建议：参数化、ORM安全操作、WAF/输入校验、最小权限数据库账号。
8. gettoken接口未授权
示例场景：公开接口可返回敏感令牌（重置令牌、登录令牌）。
漏洞成因：将内部接口引入为公网或缺失鉴权校验。
练习目标：获取他人代币并利用完成重置或登录。
修复建议：接口最小公开、严格鉴权、token单次有效与短TTL、绑定设备/会话。
9. JWT 弱键或允许 None 算法
示例场景：服务端使用弱键（易暴力破解），或错误地接受 alg=none 的无签名 JWT。
漏洞成因：JWT配置与验证实现不当。
练习目标：伪造合法JWT（提权或越权）。
步骤攻击建议：
使用jwt-tool猜测HMAC密钥或测试alg=none；
构造role=admin等禁用后访问敏感资源。
修复建议：强密钥、取消无、白名单算法、二次加密（服务端查权限）。
10. Cookie特征明显（泄露关键信息）
示例场景：Cookie 明文包含 userid/username/role 等，可被篡改导致越权。
漏洞形成原因：客户端可控信息被直接用于鉴权决定。
练习目标：修改Cookie中的身份字段以访问他人资源。
修复建议：对客户端状态做签名或只存会话ID，服务端二次鉴权与权限校验。
11. Druid 未授权访问
示例场景：/druid/ 监控面板未开启登录保护或使用默认凭据。
漏洞成因：默认配置管理面板。
练习目标：访问监控面板、查看SQL、JDBC等敏感信息，进一步横向移动。
修复建议：开启身份认证、限制来源IP、取消监控面板或网段隔离。
12.无会话机制导致越权（主键泄漏）
示例场景：业务以不可穿越主键（如openid/unionid）作为鉴权借鉴，但存在接口泄漏该主键或可推断。
漏洞成因：把“知道主键”设为“已鉴权”。
练习目标：通过获取/推断他人主键直接访问其资源。
修复建议：主键仅用于标识，不用于鉴权；每次访问必须结合会话/权限校验。
13. 两个站点鉴权机制复用（跨站点JWT/Token复用）
示例场景：同集团多个站点使用签名密钥或错误接受共识的令牌。
漏洞成因：SSO/多节点令牌加密边界模糊，信任域过大。
练习目标：在站点A登录后，携带其令牌访问站点B的设定资源。
修复建议：分域钱包、受众（aud）与发行者（iss）严格加密、令牌作用域隔离。
14. 4 补充邮箱验证码爆破
示例场景：验证码只有 4 位、无有效限速/设备绑定。
漏洞成因：验证码复杂度低、风控缺陷。
练习目标：对验证码接口进行0000-9999爆破绕过验证。
修复建议：6位以上、带字母混合；限速、重启/人机验证、错误计数锁定、设备指纹。
15. 会话覆盖
示例场景：在多步密码流程中，通过串口与会话切换覆盖验证阶段的会话归属。
攻击示例（A、B 两个账户）：
使用发起修改密码并完成验证码校验直到最后一步；
用B发起修改密码申请；
在步骤中关键用B的会话替换A的会话；
在最后一步将 A 的密码改为攻击者控制的值。
漏洞成因：流程状态与会话绑定不紧密，关键事务化与会话一致性校验。
修复：建议每一步加密会话归属与流程状态，使用令牌令牌绑定同一会话与设备。
16. 投资空参数绕过
示例场景：将某个用于鉴权或业务判断的参数设置空，头部分支因此逻辑跳过校验。
漏洞成因：支出对空值/挽回值处理不当。
练习目标：删除或置空参数以绕过权限判断。
修复建议：对丙酮值做安全默认（fail-safe），服务端重新计算关键信息而非信任客户端参数。
17.特殊字符绕过（%20、%0a等）
示例场景：路径或主机名在不同的解析出现故障，导致绕过同源/权限校验。
练习目标：使用编码空格、换行等字符绕过网关或实现路由的验证。
修复建议：统一规范化（canonicalization），在同一层处理并拒绝异常字符；白名单路径。
18. Punycode 平行越权（IDN 处理缺陷）
示例场景：乔丹将国际化域名（Punycode）错误处理为普通英文域名，从而导致错误信任。
练习目标：利用 tàrget.com（IDN）被处理成 target.com 的缺陷，巡检校验。
修复建议：严格使用IDN解析库并进行同一性比较，禁止松散字符串比较用于安全决策。
19. 弱鉴权（可直接修改 userid/username 等）
示例场景：客户端可控的身份字段被直接用于资源访问判断。
练习目标：篡改请求中的用户名/用户名以访问他人资源。
修复建议：所有资源访问必须在服务端做权限校验（基于会话/角色），客户端字段仅作显示。
20. 邮箱覆盖（非预期字段被修改）
示例场景：允许个人信息接口理论上只修改简介，但出现邮箱字段并被接受。
漏洞成因：未对可修改字段做白名单控制。
练习目标：向该接口提交邮箱参数覆盖绑定邮箱，最终可“目标邮箱+攻击者密码”登录。
修复建议：严格字段白名单、关键字段修改二次确认与强鉴权、接口契约校验。
21. 工单邮箱绕过域后缀
示例场景：企业内网登录要求特定后缀邮箱；第三方工单系统会为提交人生成工单邮箱并同步邮件。
练习目标：利用工单邮箱注册登录并接收重置邮件。
修复建议：不要仅凭邮箱后缀作为身份凭据；使用企业 IdP/SSO 与域内实名校验。
22.重置密码主机污染
示例场景：主机使用请求头 Host 重置链接（http://host/token=），可被攻击者控制。
练习目标：在受害者点击重置邮件后，令牌被投递到攻击者控制的主机。
修复建议：重建重置链接时使用服务端配置的可信域名，校验主机/引用者，链接中添加批量状态参数与绑定校验设备。
23.重置密码参数污染
示例场景：与 22 类似，但重置域名/回调地址由参数确定，可注入为攻击者域名。
修复建议：严格参数白名单与验证（固定可信回调域），拒绝任何URL；在服务端统一生成重置链接。
演练自检清单（可重复使用任何项目）
资源访问是否仅依赖客户端可控字段（userid/role/token）？
是否存在公开接口可返回敏感令牌或主键？
对验证码/重置流程是否做到了限速、设备绑定与状态一致性校验？
JWT 是否取消 none 算法、使用强密钥并加密 iss/aud？
是否存在默认密码、万能密码或继承后门？
对主机/回调URL是否做了白名单与规范化处理？
是否对管理面板（如/druid/）做了认证和来源限制？
